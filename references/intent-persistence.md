## 动机

Tier 1（recipes.md）和用户商定好动机后写入 FSRS 配置，但 **Anki 的 saveDeckConfig 只存"值"，不存"为什么"**。一旦对话结束，动机蒸发，Tier 2 诊断就退化成纯归一化——把所有用户往 FSRS 通用最优（≈ 配方 A）拉。

典型陷阱：用户选配方 B（速通，DR 0.95），诊断一看"实际 0.88 < DR 0.95−5 个百分点"就建议降 DR，**恰好毁掉用户速通的初衷**。

意图持久化就是为了把"为什么"留在磁盘上，让诊断能按用户的目标分支解释，而不是按通用最优一刀切。

---

## 路径

`intent.json` 存在 **skill 包之外**（升级/重装 skill 不丢）：

| OS | 路径 |
|---|---|
| Windows | `%APPDATA%\anki-coach\intent.json` |
| macOS / Linux | `~/.local/share/anki-coach/intent.json`（或 `~/.anki-coach/intent.json`） |

诊断时先尝试解析，失败/缺失/损坏 → 降级为"无意图"流程（见 retention-coaching.md 读意图节），不报错中断。

## 结构

per-deck（按牌组）+ global（全局兜底）。一个牌组一条记录，未单独设意图的牌组回退到 global。

```json
{
  "version": 1,
  "global": {
    "primary": "长期知识库",
    "setAt": "2026-08-12T10:00:00Z"
  },
  "decks": {
    "Japanese::JLPT": {
      "recipe": "B",
      "goal": "N2 考试冲刺",
      "deadline": "2026-12-07",
      "setAt": "2026-08-11T10:00:00Z",
      "currentDR": 0.95,
      "accepts": "高 DR 拉高负载，考前可承受"
    },
    "Default::Inbox": {
      "recipe": "A",
      "goal": "长期知识库",
      "setAt": "2026-08-11T10:00:00Z",
      "currentDR": 0.90,
      "accepts": null
    }
  }
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `recipe` | A/B/C/D/E | 配方标签。决定诊断决策树第二步走哪个分支 |
| `goal` | 自由文本 | 目标叙述（"考研""长期记命令"）。防止 recipe 标签被机械套用，保留语义 |
| `deadline` | ISO date，**仅 B 必填** | B→A/C 自动迁移的唯一触发器；无 deadline 的 B 拒绝写入 |
| `setAt` | ISO timestamp | 写入时刻。诊断用它定窗口起点 = max(setAt, 今天−90 天) |
| `currentDR` | 浮点 | 设意图时从 `getDeckConfig` 读到的实际 DR。用于交叉校验防漂移（决策树第三步） |
| `accepts` | 文本 / null | 已知权衡/免责（"高负载已接受"）。诊断命中相关现象时压制归一化建议 |

### 不存的（从 Anki 读，避免失同步）

- ❌ DR 数值范围、最大间隔、新卡量 —— `getDeckConfig` 随时读回
- ❌ `fsrsWeights` —— 同上，且 Issue #215 证实全局一套即可
- ❌ `baselineOptimalDR` —— 本字段已取消：Anki 的 CMRR 不可靠（见 retention-coaching.md），无可信基准可存
- ❌ 复习数据 —— revlog 现拉，不缓存

## 写

**时机**：recipes.md「应用」**第 4 步**，紧跟 `saveDeckConfig` + 读回验证之后，与之原子成对——配置变了意图就必须同步。

**协议**：
1. `getDeckConfig` 读回确认 FSRS 配置生效（recipes.md 第 3 步已做）
2. 从读回结果取当前 `desiredRetention` → 填入 `currentDR`
3. 和用户确认配方标签 + 目标 + （B 的）deadline + 已知权衡
4. 写 `intent.json`：按 deck 名（用 Anki 的完整 deck path，如 `Japanese::JLPT`）覆盖该条；其他牌组不动
5. 写完读回确认 JSON 合法

**配方 B 强制 deadline**：速通意图无 deadline → 拒绝写入（没有迁移触发器，"考后必须切回"守不住）。

---

## 读

**时机**：retention-coaching.md 诊断**最前置**（「读意图」节），在任何数据采集之前。

**协议**：
1. 解析 `intent.json`。失败/缺失 → 走"无意图"流程（告知用户归一化风险，问是否先设目标）
2. 按被诊断的 deck path 取记录；该 deck 无记录 → 回退 `global`；都没有 → 同上"无意图"
3. 读出 `recipe` / `goal` / `deadline` / `accepts` → 喂给决策树第二步（解释分支）和第三步（交叉校验）

## 过期

| 配方 | 过期策略 |
|---|---|
| **B** | 靠 `deadline` 自动过期：诊断时 deadline 已过 → 触发 B→A/C 迁移建议（决策树第二步）。这是 B 唯一的主动过期路径 |
| **A/C/D/E** | **完全被动**——不设周期性确认、不自动过期。仅在诊断时被读、在用户改配方时被覆盖 |
| 任何配方 | 用户主动改配方时，新决策覆盖旧记录（同 deck path 直接覆写） |

为什么 A/C/D/E 不设周期确认：符合 FSRS 维护者"减少选项、不打扰"的取向（Issue #694 Expertium）。长期目标稳定性高，定期打扰用户反成负担；真要变，用户会主动说。

## 极简（用户可见面约束）

用户**只说目标**（自然语言："我考研""学日语长期""复习太多了"），skill 内部映射到配方 + 填字段。

**绝不向用户暴露**：JSON 路径、6 个字段名、配方字母代码（除非用户问）。配置确认时只展示人话版："你这是考研冲刺（速通），考前我会按高保留率安排，考后提醒你降下来——对吗？"

理由：FSRS 维护者实证估计约一半用户不知道 DR 影响间隔长度（Issue #694）。意图层是为诊断准确性服务，不是给用户加配置项。

---

## 红线

- **只存意图，不存 FSRS 数值**。数值从 Anki 读回，存了反而要维护一致性、易失同步。
- **不以 CMRR / 最优保留率为基准**（见 retention-coaching.md）。`currentDR` 存的是"设意图那一刻的实际 DR"，不是"最优 DR"。
- **写意图必须紧跟 saveDeckConfig**，不能脱节。脱节 = 诊断失去参照 = 退化归一化。
- **配方 B 无 deadline 拒绝写入**。
- **文件在 skill 包外**，升级不丢；但迁移/重装系统需用户自行备份。诊断读到缺失/损坏不报错，降级为"无意图"流程。
