## 何时读

用户在制卡或诊断对话中表露**学习目标或场景**时路由进本文件。典型信号：

| 用户说的 | 路由到 |
|---|---|
| "我要考研 / 考 CPA / 律考 / USMLE" | 倒计时<3月 → B（速通）；>半年 → A（长期） |
| "学日语 / 西语 / 备 HSK / DELE" | 长期积累 → A；考前冲刺 → B |
| "复习太多了 / 扛不住 / 低谷期 / 复习爆炸" | C（减压维护） |
| "记 bash 命令 / 算法 / API / 语法" | D（技术碎片） |
| "记生日 / 电话 / 想替代刷手机" | E（轻度生活） |

**配置不自动触发**（见 SKILL.md description），靠 Skill 已激活时的路由表送进来。用户没主动提目标，别硬推配方。

## 总览

| 配方 | 适用 | desiredRetention | 新卡/天 | 最大间隔 | 学习步 |
|---|---|---|---|---|---|
| **A 长期可持续** | 医学生长期 / 语言长期 / 知识库 | 0.90 | 5-10 | 1000-2000d（3-5年） | 单步 10m |
| **B 速通强记** | 考试倒计时 / HSK·DELE 冲刺 / 考证突击 | 0.95-0.97 | 50-80（日历反推） | 90-180d | 5m 30m |
| **C 减压维护** | 复习爆炸 / 维护期 / 低谷 / 度假 | 0.85-0.88 | 0-暂停 | 维持原值 | 单步 10m |
| **D 技术碎片** | 编程命令 / 语法 / API / 算法 / 认证 | 0.90 | 按需低量 | 2000d | 单步 10m |
| **E 轻度生活** | 生日 / 电话 / 占星 / 替代刷手机 | 0.90 默认 | 极低 | 默认 | 默认 |

这些值经 FSRS 官方 wiki 一手背书（0.90 为默认、0.80-0.95 为合理带、>0.95 为退化区），并源自 r/Anki 真实用户案例提炼（医学生 1300 天 streak、6 年 PhD 复盘、HSK6 速通、程序员 14 年、律考倒计时等）。它们是**冷启动默认 + 心理锚，不是判决**——用户的真实复习数据（见 [`./retention-coaching.md`](./retention-coaching.md)）永远优先于配方。注：最优保留率逐用户不同，但 Anki 内置的「计算最低建议保留率」当前不可靠、且 AnkiConnect 读不到（详见 [`./retention-coaching.md`](./retention-coaching.md)），故本 Skill 不以之为基准，配方仍按场景给默认值。

## 人群每日新卡量参考（社区共识，非统计结论）

配方按**场景**分（长期/速通/减压），但同一配方下不同人群的可持续新卡量差异很大。下表是社区用户自报数据的归纳，**不是统计结论**——给配方落地时作参考，不是硬判决。

| 人群 | 可持续新卡/天 | 可信度 | 来源类型 |
|---|---|---|---|
| 语言学习（词汇：JLPT/HSK/西语等）| 10-25（默认）；配大量 immersion 可到 30-50；纯 Anki >50 几乎必崩 | 共识 | AnkiWeb 官方口吻 + 高赞多帖自报 |
| 医学生-AnKing 等预制牌 | 50-150（按课表；accelerated 短期可到 200）| 共识 | r/medicalschoolanki 高赞帖 |
| 医学生-自制牌 | ≤100（>100 易失控）| 个案 | 自报 + 经验 |
| 应试（MCAT/USMLE 类）| 60-100；>150 普遍反映吃力 | 中强 | r/Mcat 多帖一致 |
| 程序员/技术 | 5-15（且趋向更低，AI 时代语法卡在淘汰）| 弱 | 无直接数据，社区共识是"Anki 不适合记语法" |
| 法考/Bar | 30-50 | 弱 | 个案，且该人群用 Anki 比例低 |
| CPA | 不推荐用 Anki | — | 该人群几乎全靠刷题 |
| 轻度/生活（生日/电话等）| 1-5 | 弱 | 推断 |

**两个最稳的数字**（可放心引用）：

- 通用默认 **20 张/天**（Anki 默认值，AnkiWeb 官方口吻认可）
- 稳态系数 **新卡 × (8-10)**（FSRS 高保留）/ × (5-7)（DR≤80%）—— 详见 retention-coaching.md「复习负担预测」

**临界崩溃信号**（多帖一致，作预警锚点）：语言 >50/天必崩；医学生 >200/天 retention 跌到 ~60%、千级 leech；通用 复习 >300/天开始瓦解动机。

⚠ 数据局限：Anki 社区**没有正式统计研究**，上表全部源自高赞帖的用户自报。给用户推荐时，措辞用"社区共识（基于用户自报）"，别说成"统计结论"。用户的真实复习数据（见 retention-coaching.md）永远优先于本表。

## 详解

### 配方 A：长期可持续

**适用**：医学生长期、语言长期积累、研究生/PhD 知识库、任何"记一辈子"的非应试场景。

| 参数 | 值 | 为什么 |
|---|---|---|
| desiredRetention | 0.90 | FSRS 默认，长期最优。6 年 PhD 用户实测实际保留率恰好吻合 0.90 |
| 新卡/天 | 5-10（下限）| 长期党最稀缺的是复习预算。按人群差异大：语言长期 10-25、医学生长期可能 50+（见上方「人群每日新卡量参考」）。5-10 是最保守的长期下限；>10 要看复习预算扛不扛得住，用 retention-coaching.md「复习负担预测」验算 |
| 最大间隔 | 1000-2000 天 | 默认 36500（100年）不现实，社区共识设 3-5 年；最低别低于 365 天 |
| 学习步 | 单步 10m | FSRS 接管调度后多步学习已无意义，一个短步即可 |

**人群信号**：没提考试、说"想长期记住""建知识库""记一辈子"。

### 配方 B：速通强记

**适用**：考试倒计时、HSK/DELE/歌德冲刺、考证突击。

| 参数 | 值 | 为什么 |
|---|---|---|
| desiredRetention | 0.95-0.97 | 让卡几乎天天回流。语言速通党"1000 词/4 天"就靠高 DR 让卡频繁出现，短期可承受 |
| 新卡/天 | 50-80（日历反推） | 见下方公式 |
| 最大间隔 | 90-180 天 | 短期不让卡跑太远，考前都能再见到 |
| 学习步 | 5m 30m | 新卡当天多打磨两遍，对抗高 DR 带来的遗忘 |

**日历反推公式**（来自律考帖 + 官方 FAQ）：

```
新卡/天 = 剩余新卡数 / (考试剩余天数 − 14~30 天缓冲)
复习上限 = 9999（永远不限）
```

⚠ **B 不可持续**：考后必须立即切回 A 或 C，否则复习量持续爆炸。HSK6 速通用户原话"狂塞 400 卡、后几天纯复习"——这是几天的事，不是几周。考前突击完，给用户明确提示"该降 DR/降新卡了"。

### 配方 C：减压维护

**适用**：复习爆炸、医学生维护期、低谷期、度假保 streak。

| 参数 | 值 | 为什么 |
|---|---|---|
| desiredRetention | 0.85-0.88 | 降 DR 是 FSRS 时代最有效的泄压阀。DR 与负载是 U 曲线、顶端最陡：0.95→0.90 每降 1 个百分点省约 9-10% 复习；中段 0.90→0.85 约 6%；再下降边际递减（数据源：r/Anki 用户 naderking 2025-07 帖的 FSRS simulator 10 年模拟；单用户数据，相对趋势可信、绝对值因人而异）。医学生速通党主动用 0.86 压复习量 |
| 新卡/天 | 0 或暂停 | 暂停加新，只清复习。度假只做复习不做新卡（医学生 1300 天 streak 的度假策略） |
| 最大间隔 | 维持原值或略升 | 不动 |
| 学习步 | 单步 10m | 同 A |

**高阶打法——分层 DR**（社区医学生维护期共识）：把旧内容放一个子牌、DR 调低（维护模式）；新内容放另一个子牌、维持正常 DR。两副牌各自 `saveDeckConfig`。这样既减压又不误新内容。

### 配方 D：技术碎片

**适用**：编程命令/语法、API 参数、算法步骤、认证考试（LFCS/Network+）。

| 参数 | 值 | 为什么 |
|---|---|---|
| desiredRetention | 0.90 | 技术事实要长期记，同 A |
| 新卡/天 | 按需低量，约 5-15（社区弱数据）| "第二次 google 同一问题"才做卡（程序员共识）。不堆量。注：AI 时代语法卡正被淘汰，趋向更低 |
| 最大间隔 | 2000 天 | 技术事实长期有效 |
| 学习步 | 单步 10m | — |

**特殊**：卡必须原子（一条卡一个命令/一个坑点），不做整段代码卡。Anki 只攻"记忆"；"建模/拆解问题"能力靠真写代码——别让用户误以为刷卡能替代编程练习。

### 配方 E：轻度生活

**适用**：生日、电话、占星、想替代刷手机。

| 参数 | 值 | 为什么 |
|---|---|---|
| desiredRetention | 0.90 默认 | — |
| 新卡/天 | 极低，约 1-5（推断）| 生活类总量小、低频，不需要也不应高 |
| 最大间隔 | 默认 | — |
| 学习步 | 默认 | — |

**特殊**：若用户想"随时有卡刷"替代社交软件，可日上限设 0 + 只用 filtered deck——但要提醒这违背间隔重复初衷，社区老手会劝退。作为调剂可以，作为主力不推荐。

## 应用

**机制见 [`./anki-control.md`](./anki-control.md) 模板4 + 坑3**。这里只讲策略，不重复 curl。

核心四步：

1. **读全量** `getDeckConfig`（拿完整 config 对象 + 当前 desiredRetention/fsrsWeights）

⚠ **共享配置组隔离（2026-08-17 实测发现）**：多个牌组可能共用同一个配置组（新库常见：全部挂在默认组 id=1）。直接 saveDeckConfig 会波及同组**所有**牌组。改配置前先核对归属：目标牌组与其他牌组的 config id 是否相同；共享时先 `cloneDeckConfigId`（⚠ 参数是 camelCase `cloneFrom`，实测 2026-08）克隆独立配置组，改完用 `setDeckConfigId`（⚠ 参数是 `decks` **数组** + `configId`）绑定到目标牌组，再读回验证隔离（抽查一个未参与牌组的 DR 没被改动）。

2. **改字段**：只改 `desiredRetention` / 每日新卡量 / 最大间隔。**别动 fsrsWeights**——那 17 个权重必须靠 Anki 的 Optimize，手调会破坏算法
3. **写回 + 读回验证**：`saveDeckConfig` 必须传**完整** config 对象（坑3：只传部分会静默失败）；写完必须 `getDeckConfig` 读回确认生效
4. **写意图**：配置生效后，立即把本次决策写入 `intent.json`（配方标签 + 目标 + deadline + currentDR + accepts + 时间戳）。**配方 B 必填 deadline**（无 deadline 的速通意图不允许写入——没有迁移触发器，B 的"考后必须切回"就守不住）。这一步与读回验证同等级：配置变了意图就必须同步，否则诊断层会失去参照、退化成纯归一化。详见 [`./intent-persistence.md`](./intent-persistence.md)。

⚠ 字段的 JSON 路径（最大间隔在哪个子对象、每日新卡量字段叫什么）**以 getDeckConfig 实际返回为准**，别凭记忆写——Anki 版本间 config 结构会变。先打印一次返回，照着结构改。

## 红线

- **应用前必须预览 + 用户确认**（同 SKILL.md 红线1 精神）："我打算把 [牌组] 的 DR 从 0.90 调到 0.86、最大间隔设 2000 天——确认吗？"确认后再 saveDeckConfig。
- **绝不手调 fsrsWeights**（权重维度随 FSRS 版本，实测 Anki 26.05 = 21 维）。手调 = 污染算法。想让权重更新，走 [`./fsrs-optimize.md`](./fsrs-optimize.md) 的插件链路（fsrsApply，用 Anki 内置优化算法，等价点 Optimize）——这是唯一合法的自动更新路径；或引导用户点 Anki 的 Optimize 按钮。
- **配方是起点，数据优先**。如果配方说 0.90 但用户实际保留率长期 0.82（见 retention-coaching.md），按数据降 DR，别按配方硬撑。
- **FSRS 总开关的开启/关闭**走 [`./fsrs-optimize.md`](./fsrs-optimize.md) 场景 A（配套插件 fsrsSetEnabled，确认后执行，等价 GUI 勾选/取消）。纯 AnkiConnect 够不着总开关；插件没装则给一句 GUI 指引。
