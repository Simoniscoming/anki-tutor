# 预览格式与改卡指令

> 生成卡片预览、响应用户改卡指令时读本文件。
> 预览是防幻觉的最后一道关，格式要让用户一眼看完、零摩擦改卡。

## 目标

好的预览满足三条：

1. **一眼看完**：用户扫一眼就能判断这批卡对不对
2. **改起来零摩擦**：用户想改哪张，一句话就能表达，AI 零歧义解析
3. **能追溯拆卡理由**：每张卡为什么这样拆，写在表里，方便用户判断质量

## 模板

```
## 制卡预览（共 N 张）

**目标牌组**：Biology::Photosynthesis        ← 未指定时显示 Default::Inbox + ⚠ 提示
**笔记类型**：Basic / Cloze / 混合（逐卡见"类型"列）
**来源标签**：source::chat  topic::photosynthesis

| # | 类型 | Front | Back | Tags | 拆卡理由 |
|---|------|-------|------|------|---------|
| 1 | Basic | 光合作用的反应物是什么？ | CO₂ 和 H₂O | reactant | 原文有明确 Q-A 对 |
| 2 | Cloze | 光合作用把光能转化为{{c1::化学能}}，储存在{{c2::葡萄糖}}中 | — | product | 关键术语填空，一段生 2 张 |
| 3 | Basic (rev) | CO₂ 在光合作用中的角色是？ | 反应物（碳源） | reactant | 反向测，打破方向依赖 |

---

### 你可以这样回复：
- **确认写入**：回复 `OK` / `写入` / `都行`
- **改某张**：`#2 换成 Basic` / `#3 Back 改成"碳源，来自空气"` / `删 #1`
- **改全局**：`牌组改成 Biology::Exam` / `全部去掉 topic 标签` / `都加 source::chat`
- **加卡**：`再加一张：Q=光合作用的场所？ A=叶绿体`
- **重拆**：`太碎了，合并成 2 张` / `#2 太难，降低粒度`

⏸ 在你确认前，我不会写入 Anki。
```

## 六列

| 列 | 内容 | 为什么要有 |
|---|---|---|
| `#` | 序号 | 改卡指令的锚点（`#2` 指第 2 张） |
| `类型` | Basic / Cloze / Basic (rev) / 图文 | 让用户一眼看到类型分布，便于整体调整 |
| `Front` | 正面内容（Cloze 写完整 Text） | 卡片核心 |
| `Back` | 背面内容（Cloze 可写 `—`，因为自动） | 卡片核心 |
| `Tags` | 该卡专属标签（不含全局的 source/topic） | 局部标签便于单独管理 |
| `拆卡理由` | 一句话说明为什么这样拆 | **防低质量卡的关键**——强制每张卡自证价值 |

### 拆卡理由列的写法

简短即可，点明"这张卡考的是原文哪个点、用了什么制卡技巧"：
- "原文有明确 Q-A 对"
- "关键术语填空，强化回忆"
- "反向测，打破方向依赖"
- "公式核心变量"
- "对比项，双向互查"

如果某张卡的拆卡理由写不出有力的（只能写"原文提到了"），说明这张卡质量存疑，考虑加 `needs-review` 标签或丢弃。

## 改卡指令

用 `#N` 序号定位单张卡，动作用自然语言。AI 解析这些指令时要**宽松理解**，不要死扣字面。

### 单卡操作

| 用户可能说的 | AI 应该做的 |
|---|---|
| `删 #1` / `去掉第 1 张` / `#1 不要了` | 从列表移除第 1 张 |
| `#2 换成 Basic` / `#2 改成问答` | 把第 2 张的笔记类型改成 Basic（Front/Back 从 Cloze 转换） |
| `#3 Back 改成"碳源，来自空气"` | 更新第 3 张的 Back 字段 |
| `#2 加个图` | 给第 2 张嵌图（走 image-input.md 流程） |
| `#2 加 tag 难记` | 给第 2 张加标签 |

### 全局操作

| 用户可能说的 | AI 应该做的 |
|---|---|
| `牌组改成 Biology::Exam` / `全部进 Exam` | 改目标牌组 |
| `全部去掉 topic 标签` | 批量改标签 |
| `都加 source::chat` | 批量加标签 |

### 结构操作

| 用户可能说的 | AI 应该做的 |
|---|---|
| `再加一张：Q=... A=...` | 追加一张新卡到列表 |
| `太碎了，合并成 2 张` | 重新拆，减少数量 |
| `#2 太难，降低粒度` | 把第 2 张拆得更简单或换问法 |
| `重拆` | 整批重新拆 |

### 改卡后的行为

- 用户改卡后，**重新生成预览**（不是直接写入），再次 ⏸ 等确认。
- 改卡指令可能一次多条（`#2 换 Basic；删 #3；牌组改 Exam`），逐条应用后统一出新一版预览。
- 如果用户的指令有歧义（如 `#5` 但只有 3 张），**问清楚**再改，别瞎猜。

## 暂停锚点

预览结尾的 `⏸ 在你确认前，我不会写入 Anki。` 是视觉锚点，明确告诉用户"球在你这边"。

这是防护红线第 1 条（预览确认制）的体现。即使用户说"直接写别问"，也至少给一个极简预览 + 这行锚点，不完全跳过。

---

## 分批预览

单张预览表不超过 **20 张**（可读性上限）。拆出来的卡 > 20 张时分批：

- **每批 ≤ 20 张**，逐批给完整表格 + 暂停锚点 `⏸`，等用户确认这一批。
- 确认方式两种，按场景挑：
  - **逐批写入**：用户确认一批就写一批（适合用户想边看边决定去留）。
  - **累积确认后统一写入**：几批都看过、用户说"全部 OK"后一次性写入；此时仍走 `addNotes` 单批 ≤ 100 的技术分批，与这里的"预览分批"是两回事。
- 分批提示要标清"第 X/Y 批"，例如 `预览第 1/3 批（共 52 张）`。

**关键**：分批预览只解决"看得完"，**不减总量**。要减总量得在拆卡阶段按 `card-principles.md` 的 40 张总量阈值走"精简"——筛掉的卡默认不写，那才是真正减轻复习负担。

## 带查重的预览

当查重命中时（见 `dedup-strategy.md`），预览里要把命中卡的**完整对比块**列出来，不能只甩个 ID。

格式见 dedup-strategy.md 的「命中后协议」。简单说：在相似卡那行的"拆卡理由"列标注 `⚠ 与 #12345 相似`，然后在表格下方展开对比块（待写卡 / 现有卡 / 相似处），并给"跳过/更新/仍新建"三选项。

## 反例：不要这么写预览

- ❌ **不要用 JSON 预览**：用户看不懂，改不了
- ❌ **不要省略拆卡理由列**：那是防低质量卡的关键
- ❌ **不要在预览阶段就写入**：预览就是用来拦错误的
- ❌ **不要把相似卡标注简化成"⚠ 重复"**：用户没法判断，要列内容和相似处
- ❌ **不要把超长内容塞进一张预览表**：超过 20 张走分批预览（见上文「分批预览」），并在拆卡阶段按 `card-principles.md` 的 40 张总量阈值判断要不要先问"精简 vs 继续"
