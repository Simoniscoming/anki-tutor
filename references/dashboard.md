## 双通道

诊断结果**永远同时走两条通道**，这是平台适配的根本解法：

| 通道 | 内容 | 何时可用 |
|---|---|---|
| **chat 摘要**（保底） | 结构化 markdown：KPI 行 + unicode 柱 + 命中列表 + 动作 | **永远给**——任何聊天客户端都能渲染，这是云端 harness 的完整降级方案 |
| **HTML 看板**（增强） | 自包含单文件：KPI 卡片、趋势图、明细表、建议动作 | 本地 harness 完整体验；云端时文件仍落盘，供用户日后查看 |

为什么不做别的：data-URI 内嵌链接（几十 KB 的 base64）会被多数聊天端的安全过滤剥掉；上传到 paste/gist 服务会把用户学习数据发到外部，违反本 Skill 的隐私姿态；常驻本地 HTTP 服务器（brainstorming 视觉伴侣那套）是为"网页里点选回传"的双向交互设计的，看板是单向报告，静态文件 + 系统命令打开就够，没有端口、进程存活、超时这些故障点。

## 流程

诊断指标算出后，按序执行五步（1-3、5 必做，4 按环境降级）：

```
1. 填模板   读 assets/dashboard-template.html，edit-in-place 换成实测数据
2. 写文件   存到 %APPDATA%\anki-coach\dashboards\<ASCII 时间戳>.html
3. 落历史   往 %APPDATA%\anki-coach\dashboard-history.json 追加本次快照
4. 开浏览器 本地环境 → 用 OS 矩阵命令打开；远端聊天 → 跳过（见「降级链」）
5. chat 摘要 按下方模板在对话里给 markdown 版 + 文件路径
```

## 模板

**模板在 [`../assets/dashboard-template.html`](../assets/dashboard-template.html)**（已用示例值填好），成品长什么样看 [`../assets/dashboard-example.html`](../assets/dashboard-example.html)。规则：

- **edit-in-place，别从零写**。模板每个块都有示例值和 ★ 注释，逐处替换、按需复制/删除重复块（KPI 卡、柱条、表格行、alert、词条），填完删除全部 ★ 注释。
- **柱状图**：每天一根柱，`height = 当日量 ÷ 窗口最大量 × 100%`（取整）；超过容量参考线的柱加 `hot` 类；零值日保留 0%（有 2px 柱底），备注里写明「没柱子的日子 = 完全没复习」。
- **保留率对比条**：fill 宽 = 实际保留率%，DR 刻度线 `left` = DR%；差 −5pp 以上用 `err` 红、0~5pp 用 `warn` 黄、达标用默认蓝。**样本不足时不画对比条**，整个 value 区换成 insufficient 提示（见下）。
- **样本不足的块如实标**：mature 复习 < 200、窗口 < 30 天时，对应 KPI 卡写「数据还不够（只统计到 N 次，满 200 次才能下判断）」，不显示误导性数字；可补一行灰色参考（如含新卡的总答对率）但必须注明「新卡答错很正常」。
- **没算的块直接删**：诊断没做 note 聚合就删贵概念表，没有 leech 就删表换成一条 ok alert（「没有忘记超过 8 次的卡」）。看板宁可短，不可编。
- **预测卡红线**：数字依据必须是**实测新卡引入速率**（collect JSON 的 `forecast.basis=="actual"`），不是牌组设置里的新卡上限——上限只是水龙头开度，没在跑就不算数。`basis=="config-assumption"`（最近没在加新卡）或 `forecast` 为 null 时，整卡显示「—/不适用」并用人话解释；任何预测不得大于该牌组总卡数（`cappedByTotalCards=true` 时必须注明受总量封顶）。反面案例（2026-08-16）：5 张卡的测试牌组被报「≈180 张/天」，就是错把设置上限当实际流量，用户一眼识破。

## 写作语言（小白友好，硬规则）

**读者假设：不懂 DR、retention、lapses 是什么的人。** 看板是说给他听的体检报告，不是给算法工程师的监控面板。

1. **人话在前，术语进括号**。KPI 标签、alert 标题、区块标题一律人话；术语只出现在 `.term` 小灰字、括号注释和名词解释区。英文缩写（DR/FSRS/lapses）不单独出现在标题和大数字里。
2. **每个数字回答「这意味着什么」**。「84.1% vs DR 90%」不合格；「比目标低 5.9 个百分点——不是偶然，真的偏低了」合格。每个 delta 行都要让读者知道该高兴、该警惕、还是无所谓。
3. **名词解释区必须保留**（原生 `<details>` 折叠，零 JS），且只留本页真出现的词。读者不需要时它不占地方，需要时点开就有。
4. **不吓唬人，也不粉饰**。「样本不足」说「还在观察中，不是没问题」；「量会涨」说清是规律不是故障；负面信号给出路（建议动作区接住）。
5. **术语 → 人话对照**（生成时照此翻译，表格没列的词按同样思路转译）：

| 术语 | 看板上写 |
|---|---|
| 实际保留率（mature retention） | 复习时能想起来的比例（只算长期卡） |
| desiredRetention / DR | 目标 |
| interval > 21 天（mature） | 长期卡（间隔超过 21 天，才算真记住） |
| Backlog | 积压的复习（欠账）——按现在的速度几天能清完 |
| streak | 连续打卡 |
| leech | 老是记不住的卡（同一张忘了 8 次以上） |
| lapses | 忘了几次 |
| reps | 总共复习 |
| 稳态预测 / k 系数 | 以后每天大概要复习多少（每张新卡日后约带来 8~10 次复习） |
| FSRS 优化 | 重新校准（让算法复习功课） |
| 配方 A/B/C | 你的目标：长期记住 / 考前冲刺 / 减压维护 |
| 三道闸 | 差距够大 + 数据够多 + 持续够久（三个条件都满足才算真的偏低） |

## 存放

| OS | 看板目录 | 历史文件 |
|---|---|---|
| Windows | `%APPDATA%\anki-coach\dashboards\` | `%APPDATA%\anki-coach\dashboard-history.json` |
| macOS / Linux | `~/.local/share/anki-coach/dashboards/` | `~/.local/share/anki-coach/dashboard-history.json` |

与 `intent.json`、`optimize-log.json` 同根目录（skill 包外，升级不丢）。**文件名只用 ASCII**：`YYYY-MM-DD-HHMM.html`（如 `2026-08-16-1430.html`），一次诊断一个新文件、绝不复用。牌组名**不进文件名**（中文牌组名过 Windows cmd 有编码风险），写在 HTML 的 `<title>` 和页头里。目录不存在先 `mkdir -p`。

## OS 矩阵

写完文件后用系统默认浏览器打开：

| 环境 | 命令 | 坑 |
|---|---|---|
| Windows（Git Bash） | `cmd //c start "" "<Windows 路径>"` | `start` 是 cmd 内建不是 exe；`//c` 双斜杠防 MSYS 路径改写；`""` 是窗口标题占位，缺了会把路径当标题 |
| Windows（备选） | `explorer.exe "<Windows 路径>"` | **返回码 1 也算成功**，别当失败重试 |
| macOS | `open "<路径>"` | — |
| Linux | `xdg-open "<路径>" >/dev/null 2>&1` | 常吐无害警告、返回非零，吞掉即可 |

Git Bash 里 `%APPDATA%` 写作 `"$APPDATA"`；Windows 路径转换可用 `cygpath -w`。**打开失败不重试**——降级为在 chat 摘要里给出文件完整路径，让用户自己点开。

## 降级链

**判断不了就先按本地走**（第 4 步照做），用户说「看不到」后当轮降级、同会话后续诊断直接走降级模式：

| 环境 | 特征 | 行为 |
|---|---|---|
| 本地 harness（默认假设） | Claude Code / ZCode 跑在用户机器上 | 完整五步，浏览器自动打开 |
| 远端聊天（OpenClaw 网关类） | agent 在用户机器上能拉到 AnkiConnect 数据，但聊天界面在手机/远端，用户反馈看不到 | 跳过第 4 步，其余照做；文件留在磁盘供日后看；**chat 摘要就是本次的完整交付**；平台支持往聊天传文件就传一份 |
| 完全云端 | agent 连 `localhost:8765` 都不通 | 诊断本身无法进行（数据都拉不到），不涉及看板问题——先解决连接 |

降级链：开浏览器 → 给路径 → 纯 chat 摘要。任何一级失败就退到下一级，不报错中断。

## history

`dashboard-history.json` 存**每次诊断的极简快照**，为将来的趋势看板（「跟上月比」）积累数据。与 intent.json 同哲学：Anki 不存的东西，skill 自己造真相源。

```json
{
  "version": 1,
  "entries": [
    {
      "ts": "2026-08-16T14:30:00+08:00",
      "deck": "日语::JLPT N2 词汇",
      "windowDays": 30,
      "dr": 0.90,
      "actualRetention": 0.841,
      "matureReviewCount": 412,
      "gatesPassed": true,
      "backlogDays": 3.2,
      "streakDays": 41,
      "forecastPerDay": 45,
      "forecastBasis": "actual",
      "leechCount": 3,
      "hits": ["retention-low", "optimize-due"],
      "fsrsEnabled": true,
      "daysSinceOptimize": 42,
      "htmlFile": "2026-08-16-1430.html"
    }
  ]
}
```

- **写**：第 3 步，读文件 → `entries` 末尾 push 本次 → 写回。缺失/损坏 → 重建 `{version:1, entries:[...]}` 从头攒，不报错。
- **读**：将来做趋势对比时用；当前版本诊断时**不读**（不给自己找参照干扰）。
- 字段尽量精简——存的是「能画趋势线」的最小集，明细都在 HTML 里。

## chat 摘要

chat 通道的固定形态（HTML 看板的浓缩版，**语言同样按「写作语言」规则说人话**，数字必须与 HTML 一致）：

```markdown
📊 学习体检报告 · <牌组名> · <日期 时间>（看最近 30 天）
├ 智能排期 FSRS：✅ 已开启 · 3 天前刚校准过
├ 能想起来的比例：还在观察中（长期卡数据 23 次，攒满 200 次才能判断）
├ 欠账：2.1 天的量，健康 ✅ ｜ 这个牌组连续打卡：1 天（30 天里 10 天没碰）
├ 以后每天要复习多少：预测 ≈174 张/天（你现在实际 ~24 张/天，会有个爬坡过程）
├ 发现 1 个提醒：按「每天 20 张新卡」的设置，1-3 个月后复习量是现在的 7 倍——确认这是你想要的
└ 接下来（你来选）：1. 调低每天新卡量（改前先给你看方案） 2. 保持现状几周后再测 3. 告诉我你的学习目标

📄 完整报告（带图表和名词解释）：<文件完整路径>
```

unicode 柱用 ▁▂▃▄▅▆▇█ 八档，按当日量相对最大值取档，可用于「最近复习节奏」一行。远端聊天环境删掉最后一行路径或改说「报告已存盘」。

## 红线

- **看板纯展示**：不因生成看板而多拉数据、不改任何配置或卡片。诊断的只读红线覆盖看板层。
- **模板禁一切外部资源**（CDN、字体、图片、JS）——离线可用 + 零数据外泄，这是能放心打开任意生成文件的前提。
- **数字必须来自本次实测**，禁止编造；样本不足如实标注，宁缺勿假。
- **页脚经验值声明不可删**（DR−5pp、样本 200、lapses≥8、backlog 7/14 天、系数 k 全是启发式）。
- 涉及写操作的建议（优化 FSRS、降 DR、删卡）在看板里只列动作并注明「需确认后执行」，看板本身不触发任何写。
