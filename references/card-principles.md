## 首选方案：调用内置 twenty_rules prompt

anki-mcp（v0.6.0+）**内置了一个 `twenty_rules` prompt**，内容就是 Dr. Piotr Wozniak 的《Twenty Rules of Formulating Knowledge》——SuperMemo 创始人几十年研究的制卡黄金标准。

**拆卡时首选调用它**，让 AI 按 20 条法则拆。它覆盖：

1. 不理解就不制卡（理解优先）
2. 先学整体再记细节（建立大图景）
3. 建立在基础之上（简单先于复杂）
4. 最小信息原则（一张卡一个点）
5. Cloze 填空简单有效
6. 用图像（视觉记忆强大）
7. 用记忆法（口诀、联想）
8. 避免 Sets（大列表是记忆杀手）
9. 避免枚举
10. 对抗干扰（让相似卡片有区分度）
... 等 20 条

> 调用方式见 anki-mcp 文档；在 Claude Desktop 通过附件菜单 "Add from Anki MCP Server" 选 "Twenty rules"。本 Skill 在工作流第②步就该触发它。

**为什么不自己重写这 20 条**：内置 prompt 由 anki-mcp 官方维护、跟着版本更新、经过测试。自己重写一份等于重复造轮子，还会和官方版本产生分叉（你课程说的 DRY 原则）。

## 补缺口

内置 prompt 覆盖了 20 条法则，但有几个**实操层面的缺口**它没讲，本文件补上。这些是制卡时最容易翻车的细节。

### 缺口 1：质量闸门（每张卡的自检清单）

内置 prompt 说"要原子化、要简单"，但没给**怎么判断一张卡到底过没过关**。补上自检清单——见下方「质量闸门」。

### 缺口 2：数量上限

内置 prompt 没说**一段文本该拆几张**。AI 容易拆太多或太少。补上经验值——见下方「数量上限」。

### 缺口 3：中文措辞的"没拆干净"信号词

内置 prompt 是英文写的，没针对中文卡片给"识别没拆干净"的信号词。补上——见下方「信号词警示」。

### 缺口 4：预览时的"拆卡理由"自证

内置 prompt 不管预览环节。本 Skill 要求每张卡在预览表里写"拆卡理由"，强制自证价值（见 preview-format.md）。这是防低质量卡的关键。

## 质量闸门

拆卡时对每张卡自问这几个问题，有一条答"否"就考虑丢弃或合并：

- 这张卡考的是**单一明确**的知识点吗？（不是"这段话说了啥"）
- 这个知识点**值得长期记**吗？（不是一次性信息）
- 用户**未来真的会用**到这个吗？（不是"可能考但其实没用"）
- Front 提问**无歧义**吗？（不会有多种合理解读）
- Back 答案**简短**吗？（一句话能答完，不需要长段）

**没全部过关的卡**：要么回炉重拆，要么加 `needs-review` 标签提醒用户重点看，要么直接丢弃并告知用户"第 X 条信息密度不够，建议跳过"。

---

## 数量上限

内置 prompt 没给数量指引，但实际拆卡要有节制：

- **单段文本**（约 100-200 字）：通常拆 2-5 张原子卡。超过 5 张要警惕是否在堆砌。
- **主动减量**：拆到一半发现某些信息不值得长期记，主动告诉用户"第 X、Y 条价值不高，建议跳过"。

这些是经验值，不是硬规则——核心还是看每张卡是否过质量闸门。

### 预览分批（展示，20 张/批）

单张预览表不超过 **20 行**（用户看得完的上限）。拆出来的卡 > 20 张时，**分批预览**：每批 ≤ 20 张，逐批给暂停锚点 `⏸` 等确认。具体格式见 `preview-format.md`。

注意：分批只解决"预览看得完"，**不减总量**——和写入数量的决策是两回事。

### 总量阈值（负担，40 张）

**40 张**是单次制卡的总量警戒线，保护的是用户复习时的记忆负担和 FSRS 调度，不是预览表格放不下。按拆出的张数分两种走法：

- **≤ 40 张**：正常做。> 20 的部分走分批预览，但写入总量不变。
- **> 40 张**：预览前**先问**用户"约 N 张，偏多。精简到核心、还是继续全部？"别默认减量，也别默认全灌——把决策交还用户。
  - **精简** → 按质量闸门筛到 40 及以下。**被筛掉的默认不写**（这是唯一能真正减轻复习负担的动作），告知用户"筛掉了 X 条偏边角/低密度的，没进 Anki，需要的话再单独说"。
  - **继续**（用户明知超 40 仍坚持要全部）→ 尊重用户，全部保留、分批预览、全部写入。只提醒一句"这批会新增 N 张，复习负担较重"，不拦。

**为什么上限不能靠"调高数字一次性灌库"**：分批**写入**和一次性写入对复习队列是同一个结果——FSRS 只看牌库里多了多少张新卡，不在乎你分几次 add。所以真正能减负担的只有"真的不写"。超量时优先"询问 + 真减量"，而不是"调高数字"。

## 信号词警示

中文卡片里，如果一张卡的 Back 出现这些词，**多半是没拆干净**，回去再拆：

- **"以及""此外""同时""并且"**：说明 Back 里塞了多个并列点
- **顿号连缀很多项**（"A、B、C、D、E"）：枚举，违反避免枚举原则
- **"等等""等"**：说明答案不完整或开放
- **"例如……"** 后接多个例子：例子该独立成卡或精简

英文卡片的对应信号：`and also`、`as well as`、`including ...`、`such as`、长串逗号。

## 反例

### 反例 1：大段照抄（违反最小信息）

```
❌ Front：简述牛顿第三定律。
   Back：牛顿第三定律指出，两个物体之间的作用力和反作用力总是大小相等、方向相反……
问题：Back 太长，考的是"背课文"。质量闸门"Back 简短"不过关。

✅ 拆成单点卡：
   Front：牛顿第三定律描述的是哪两个力的关系？→ 作用力与反作用力（大小相等、方向相反）
   Front：作用力和反作用力作用在几个物体上？→ 两个（分别作用在两个不同物体上）
```

### 反例 2：枚举（违反避免枚举）

```
❌ Front：列举 TCP 三次握手的步骤。
问题：枚举，难记顺序。信号词"列举"触警。

✅ 每步拆成单点卡：
   Front：TCP 三次握手中，客户端发的第一个包标志位是什么？→ SYN
   Front：三次握手后连接处于什么状态？→ ESTABLISHED
```

### 反例 3：单向卡漏反向（违反双向）

```
❌ 只有：Front: "Photosynthesis" → Back: "光合作用"
问题：只练了英→中，反着问会卡。

✅ 用 Basic (and reversed card) 模型，自动生成双向卡。
```

### 反例 4：Back 信号词触警（没拆干净）

```
❌ Front：细胞呼吸的产物有哪些？
   Back：CO₂、水、以及少量 ATP，此外在某些情况下还会产生乳酸。
问题："以及""此外"触警，Back 塞了多个点。

✅ 拆开：
   Front：细胞呼吸的主要气体产物？→ CO₂ 和水
   Front：细胞呼吸中 ATP 在哪几个阶段产生？→ （再拆成糖酵解/三羧酸循环/氧化磷酸化各一张）
```

## 与内置 prompt 的协作总结

| 谁 | 负责什么 |
|---|---|
| anki-mcp 内置 `twenty_rules` prompt | 20 条法则的完整内容、怎么拆的原理 |
| 本文件（card-principles.md） | 质量闸门、数量上限、中文信号词、反例、预览拆卡理由约定 |

调用内置 prompt 拆完卡后，**用本文件的闸门和信号词再过一遍**，把没过卡的筛掉。两道工序配合，质量才有保障。
