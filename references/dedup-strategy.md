# 查重去重策略

> 写入卡片前读本文件，决定怎么查重、命中怎么处理。
> 查重是防止"同一知识点被重复复习"的关键。

## 为什么

Anki 是基于间隔重复的——同一知识点如果存在多张相似卡，会被算法多次排进复习队列。后果：

- **浪费时间**：同一个点反复出现，挤占其他知识点的复习预算
- **打乱 FSRS 调度**：FSRS 根据答对率估算记忆强度，重复卡会让某知识点"显得"掌握得更好，干扰算法判断
- **挫败感**：复习时反复遇到似曾相识的卡，"这题我不是刚做过吗"

社区共识：**宁可漏不可重**——宁可没查出来（漏），也不要瞎标重复（错杀好卡）。

---

## 两个层次

1. **精确匹配**：待写卡的 Front 和现有某张卡的 Front 几乎一模一样。
2. **语义近似**：问法不同，但考的是同一个知识点。

查重要兼顾两层，但优先抓精确匹配（成本低、误判少）。

---

## 怎么查

对每张待写卡：

1. **提取关键词**：从 Front 抽 2-3 个核心关键词（去掉"是什么""的""吗"等虚词）。
2. **搜目标牌组**：调 `findNotes`，查询串形如 `"deck:目标牌组 关键词1 关键词2"`。
   - 只搜目标牌组，不搜全库（不同牌组可能故意重复，见「边界」）。
3. **看现有卡内容**：对命中的 note，调 `notesInfo` 拿 Front/Back 全文。
4. **判相似度**：按下方判据，决定跳过/保留/让用户选。

### 工具调用示意

```
findNotes(query: "deck:Biology::Photosynthesis 光合作用 反应物")
  → 命中 [1234, 5678]
notesInfo(notes: [1234, 5678])
  → 拿到这两张卡的 Front/Back，比对
```

## 相似度判据

这是给 AI 的判断标准，不是硬算法——靠语义理解。

| 相似度 | 判断 | 处理 |
|---|---|---|
| **高相似** | 同一知识点 + 同一问法（措辞略异）| 建议跳过 |
| **高相似** | 同一知识点 + 不同角度但答案一致 | 建议跳过或合并 |
| **中相似** | 同一知识点 + 真正不同的角度 | 保留，但预览里给用户看 |
| **低相似** | 只是关键词撞了，知识点不同 | 放行，不标注 |

判断要点：
- **比知识点，不只比字面**。"光合作用的反应物"和"光合作用需要什么原料"是高相似（同点）。
- **角度不同才算独立卡**。"反应物"和"产物"是不同知识点（低相似，都保留）。
- **Cloze 挖的不同位置算不同卡**，即使同一段 Text。

## 命中后协议

命中相似卡时，**不要自作主张跳过，也不要只甩一个卡 ID 让用户自己去查**——要把判断所需的全部信息摆在用户面前。

### 预览里的标注格式

对每张命中相似卡的待写卡，在预览表下方（或紧跟该卡）列出对比块：

```
⚠ #2 与现有卡 #12345 相似，疑似重复：

   待写 #2：
     Front: 光合作用的反应物是什么？
     Back:  CO₂ 和 H₂O

   现有 #12345：
     Front: 光合作用需要什么原料？
     Back:  CO₂ 和 H₂O

   相似处：问的都是光合作用的反应物（CO₂ 和 H₂O），问法不同但知识点一致 → 高相似
```

**标注三要素**（缺一不可）：
1. **现有卡的完整内容**：Front + Back 都列出来（用户不该为了判断再去 Anki 里翻）
2. **待写卡的完整内容**：方便对照
3. **相似之处**：一句话点明为什么判定相似（哪个知识点重合 / 答案是否一致）

### 用户可选的三选项

在预览下方的"你可以这样回复"里给出：

- `跳过 #N`：不写这张（推荐选项，默认）
- `#N 改成更新现有`：用新内容更新 #12345
- `#N 仍新建`：强行新建（用户确认知道重复）

### 默认行为

**用户没明确选择时，默认跳过并告知**："第 2、3 张与现有卡重复，已跳过。需要的话告诉我仍新建。"

## 边界

### 不查重的情况

- **跨牌组不查**：只搜目标牌组。如果用户把同一概念分别放进"英语"和"医学"两个牌组（语境不同），那是用户的选择。
- **用户明确说"知道重复就是要建"**：直接跳过查重，写入。但预览里仍可提示一句"与现有卡 X 相似，已按要求新建"。
- **第一次制卡（库是空的）**：findNotes 必然空结果，不必跑——但跑一下也无妨，确认牌组里确实没东西。

### 查重的局限（诚实说明）

- **findNotes 是关键词搜索**，不是语义搜索。同义词查不出来（"光合作用" vs "photosynthesis" 可能漏检）。
- **只能查当前牌组**。如果用户在不同牌组已有相似卡，查不到。
- 所以查重是**降低重复概率**，不是消除重复。告诉用户这是尽力而为。

## 示例

### 例 1：高相似 → 建议跳过（完整对比块）

```
待写卡：Front="光合作用的反应物是什么？"
findNotes("deck:Bio 光合作用 反应物") → 命中 #12345
notesInfo → 现有卡 Front="光合作用需要什么原料？" Back="CO₂ 和 H₂O"

判定：高相似（同知识点"反应物"）

预览标注：
  ⚠ 与现有卡 #12345 相似：
     待写：光合作用的反应物是什么？ → CO₂ 和 H₂O
     现有：光合作用需要什么原料？ → CO₂ 和 H₂O
     相似处：问的都是反应物，答案一致 → 建议跳过
```

### 例 2：高相似（不同问法同点）→ 建议跳过

```
待写卡：Front="叶绿体在光合作用中的作用？"
现有卡 #99：Front="光合作用发生在哪个细胞器？" Back="叶绿体"

判定：高相似（都指向"叶绿体=光合作用场所"）
标注：
  ⚠ 与 #99 相似：
     待写：叶绿体在光合作用中的作用？ → （光合作用的场所）
     现有：光合作用发生在哪个细胞器？ → 叶绿体
     相似处：都指向"叶绿体是光合作用场所"，正反问法 → 建议跳过
```

### 例 3：低相似 → 放行（不标注）

```
待写卡：Front="光合作用的产物是什么？"
现有卡 #12345：Front="光合作用的反应物是什么？"

判定：低相似（产物 vs 反应物是不同知识点）
处理：不标注，正常放行
```

### 例 4：中相似 → 保留但提示

```
待写卡：Front="FSRS 算法的核心目标是什么？"
现有卡 #77：Front="FSRS 是什么？" Back="一种间隔重复调度算法"

判定：中相似（都讲 FSRS，但一个问定义、一个问目标，角度不同）
标注：
  ℹ 与 #77 主题相近但角度不同：
     待写：FSRS 算法的核心目标是什么？
     现有：FSRS 是什么？ → 一种间隔重复调度算法
     相似处：同属 FSRS 主题，但问的是不同侧面 → 保留
```

## 工程取舍

**dedup 是"近似判断"，不写脚本。**

- 查重的核心是**语义相似度判断**，这需要 AI 的语言理解能力，不适合下沉成 shell 脚本（脚本只能做关键词匹配，做不了语义）。
- findNotes/notesInfo 是确定性工具，由 AI 调用即可，不需要额外封装。
- 所以本策略全部用 prompt + 工具调用实现，没有 `scripts/dedup.py`。

如果未来发现查重频繁出现误判，再考虑引入相似度脚本（如 embedding 比对），但那依赖额外服务，v1 不做。
